Project 'retro game library' (org/projects/retro-game-library.md, status active, owner brad, no repo). Brad wants one place to browse and launch a retro collection with good metadata. Incumbents ruled out by Brad: Pegasus (no stable release since weekly_2024w38, metadata user-maintained) and LaunchBox (closed source, Big Box is a paid unlock). card-017 ran the options research (12 candidates, four models). decision-009 scoped it: Windows desktop frontend, no server, and PSP + multi-disc handling is the discriminator.

Verification pass against upstream source: Playnite (MIT, 14,393 stars, pushed 2026-10-19, release 10.63) is the leader - the shipped PPSSPP profile covers iso/cso/pbp/chd on sony_psp via PPSSPPWindows64.exe, source/Playnite/Common/M3U.cs parses playlists including RetroArch's ':'/'|' suffixes, and Scanner.cs treats .m3u/.cue/.gdi as playlists and groups '(...Disc 1)' style files into one game. Caveat: LaunchBox survives there only as a metadata provider plugin - no library importer - so the game list is re-scanned. SimpleLauncher (GPL-3.0, 266 stars, pushed 2026-10-30, release 5.8.4) is the challenger: PSP searches cso/chd/iso/pbp/elf/prx and ChdMountStrategy + DiscConverter are the deepest disc machinery found (CHD mount on 19 emulators, CHD->ISO, CHD->CUE/BIN, PBP->CUE/BIN), but no automatic m3u generation, no LaunchBox import, metadata limited to RetroAchievements + image packs. ES-DE out (multi-disc is hand-authored .m3u directories; psp = PPSSPP single disc image). Pegasus out (0 m3u code hits, no stable release in two years) despite shipping a LaunchBox data provider. OpenBoxGL out (localhost server architecture fails the ruling; PSP def has no chd).

card-018 existed to trial Playnite + SimpleLauncher on Brad's real folders, and it is **done as of 2026-11-01**. Both ran as portable copies under F:\Lab\trials\ against E:\Sony\PSP (33 ISOs) and E:\Sony\PSX (52 CHDs, 23 discs in 9 multi-disc sets, zero .m3u anywhere). **Verdict: Playnite passes the discriminator, SimpleLauncher does not.** Joining Playnite's LiteDB stores (games.db + platforms.db + emulators.db + sources.db + scanners.db) gives the accurate numbers: 76 Game documents = 33 PSP + 38 PSX holding all 52 disc files, with **9 entries holding >1 disc** (histogram 29x1, 6x2, 1x3, 2x4), all 85 rom paths resolving, disc grouping driven by `MergeRelatedFiles: true`, PSP bound to the builtin PPSSPP profile and PSX to Beetle PSX HW, both through F:\RetroArch (InstallDir F:\RetroArch). Playnite auto-imported **text** metadata on 74/76 (description, release date, genre 73, publisher 72, developer 71, series 66, links 70) and set `Image` on **0** - artwork is NOT auto-filled, that earlier claim was wrong. Playtime 848 / PlayCount 1 on GTA - Chinatown Wars from the live PSP launch (playnite.log shows retroarch.exe -L ppsspp_libretro.dll + the ISO); the 5 Steam entries' playtime is inherited from Steam, not measured. Playnite's multi-disc semantics are source-level: GamesEditor.cs:1716-1728 makes one play action per disc named '<Game>: <Disc N>' (manual pick, plain Play uses Roms[0]) and it never generates an .m3u. SimpleLauncher scanned 33 PSP tiles and 52 PSX tiles - every disc its own tile, no collapse, no generated .m3u - and persists **no game list at all**: settings.dat is SQLite tables Meta/AppSettings/EmulatorSettings/Favorites/PlayHistory/Systems/SystemPlayTimes, tiles re-scanned from SystemFolders each startup, its per-system config has no disc or playlist field (only GroupByFolder). Its live PSP launch also passed (PlayHistory 1 / TotalPlayTime 287). Disposal, per Brad's "delete what doesn't matter": the app trees, portable .NET 10 and installers are deleted (1,794 MB); what remains is F:\Lab\trials\evidence\ - 25 files, 2.2 MB, SHA256-listed in F:\Lab\trials\evidence\MANIFEST.txt, deliberately untracked because trials\ is gitignored. There was never a F:\Lab\trials\plbak\ backup - Brad has no installed Playnite, so nothing of his was ever at risk. E:\Sony was written 0 times. F:\RetroArch was never edited by us, but RetroArch rewrote its own retroarch.cfg and playlists (content_history.lpl, a new PPSSPP log) when the trial launched a game - normal behaviour on exit; pause_on_window_lost_focus is still unset, so an unfocused RetroArch window renders black. Open decision is Brad's: adopt Playnite for real means a non-trial install plus what to do with his existing LaunchBox data (Playnite imports its metadata, not its game list), and artwork is separate work.
